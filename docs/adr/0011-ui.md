# ADR-0011: Web UI technology (M1)

**Status:** Accepted (2026-11-21)

## Options considered
| Option | For | Against |
|---|---|---|
| **A. Go `html/template`, server-rendered, embedded with `go:embed`** | Single binary; contextual auto-escaping; no JavaScript at all; no second build | Less suited to very rich client-side interaction |
| B. React/TypeScript SPA | Rich UI; large hiring pool | npm supply chain; a second toolchain; the API must be complete before the UI works |

## Decision
Option A for M1-M2.

- **Shared logic:** the UI calls the same service layer as the API, with the same authorization checks.
- **Browser protections:** strict CSP with no inline script; CSRF tokens on forms; `SameSite=Lax` session cookies.
- **No JavaScript:** plain forms and links only, so the CSP can forbid scripts entirely. If a later screen needs partial updates, htmx can be vendored at a pinned version with an SRI hash; that is a new decision, not a default.

Revisit at M3 if the workflow and approval screens need richer interaction.

Every dashboard metric shows its definition and denominator, and links through to the items behind it.
