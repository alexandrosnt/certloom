# ADR-0010: Public API style and contract

**Status:** Accepted (2026-11-21)

## Context
The API serves the CLI, the UI, webhooks and IaC consumers (Terraform/Ansible from
Phase 6). It needs stable resource IDs, pagination, concurrency control, idempotency
and clear errors.

## Facts (checked 2026-11-20)
oapi-codegen v2.8.x has had "initial" OpenAPI 3.1 support since v2.8.0. Its 3.0.x support is mature.

## Options considered
| Option | For | Against |
|---|---|---|
| **A. REST/JSON, spec-first OpenAPI, Go server stubs and client generated by oapi-codegen** | Works with curl/IaC/webhooks; a single contract feeds the docs, the CLI client and the tests | Code generation adds a build step |
| B. gRPC with a gRPC-Gateway JSON layer | Strong typing, streaming | Awkward for IaC and webhook consumers; two surfaces to document |
| C. Hand-written REST, no spec | Fastest to start | Drifts; no generated clients; weak compatibility guarantees |

## Decision
Option A. **The spec is written in OpenAPI 3.0.3 for M1.** We move to 3.1 once
oapi-codegen's 3.1 support is no longer marked "initial", or once a 3.1-only feature is needed.

Conventions:
- **Paths:** `/api/v1/...` versioning. Breaking changes require `/v2`, and `/v1` stays supported for at least two minor releases.
- **IDs:** ULIDs with a type prefix (`crt_...`, `ept_...`).
- **Pagination:** opaque cursor (`?cursor=...&limit=...`).
- **Concurrency:** `ETag` / `If-Match` on mutable resources; a mismatch returns 412.
- **Idempotency:** an `Idempotency-Key` header on POSTs that create something or start work. Keys are kept for 24 h.
- **Errors:** RFC 9457 problem details with stable `type` URIs, a `request_id`, and `remediation` hints.
- **Dry runs:** `?dry_run=true` on every mutation, returning the plan and the policy evaluation.
- **Rate limits:** per token, with `RateLimit-*` headers.
- **Agent channel:** a separate HTTPS + JSON API over mutual TLS on its own listener (ADR-0004). It is not part of the public contract.

## Verification
- CI checks that the spec validates and that the generated code is up to date.
- Contract tests run against a live `certloomd`.
- A breaking-change detector (oasdiff) runs on pull requests.
